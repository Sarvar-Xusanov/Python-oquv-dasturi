# PART 1. PROJECT IDENTITY AND VISION

## 1.1 Product identity

Product name: Python Mastery
Tagline: Learn Python. Build Skills. Create the Future.
Product type: Universal multi-user desktop educational application.
Platforms: Kali Linux, Debian, Ubuntu, Windows 10/11.
Languages: Uzbek and English.
Default interface language: Uzbek.

Programming terminology must remain in English, accompanied by clear Uzbek explanations.

## 1.2 Product objective

Build a complete Python education ecosystem that allows anyone to learn programming from absolute zero to advanced practical competency.

The product combines:
1. A complete educational curriculum.
2. An AI personal tutor.
3. An integrated Python IDE.
4. Interactive exercises.
5. Automated examinations.
6. Real-world projects.
7. Video learning resources.
8. Personal learning analytics.
9. Multi-user profile management.
10. Course and content management.

This must be a real application, not a static mockup or website prototype.

## 1.3 Target audience

Support:
- Absolute beginners with no programming knowledge.
- Students who know basic computer concepts.
- Learners with introductory Python knowledge.
- Intermediate Python developers.
- Advanced learners.
- University students.
- Self-taught programmers.
- People preparing for Junior Python Developer roles.

Use one standardized knowledge framework, while personalizing each user's learning experience.

## 1.4 Learning principle

Use this learning cycle:

UNDERSTAND → OBSERVE → PRACTICE → SOLVE → TEST → REVIEW → BUILD.

Watching a video or reading a lesson is not proof of programming competence. Students must demonstrate understanding through practical work.

# PART 2. TECHNOLOGY STACK

Choose stable, mutually compatible dependency versions. Document the selected versions and lock dependencies.

## 2.1 Main application
- Python 3.12 or newer, provided all selected dependencies support it.
- PySide6.
- Qt Widgets.
- SQLAlchemy 2.x.
- Alembic.
- Pydantic.
- Markdown rendering.

## 2.2 Graphics and interface libraries

| Package | Responsibility |
|---|---|
| PySide6 | Main desktop UI |
| QScintilla | Python code editor |
| PyQtGraph | Interactive progress charts |
| Matplotlib | Advanced charts and reports |
| QSS | Global interface styling |
| Pillow | Image processing |
| QtSvg | SVG rendering |
| Qt Animation | Interface transitions |
| Lucide SVG assets | Consistent icons |

Do not install multiple libraries for the same task without a clear reason. Use PyQtGraph for lightweight interactive statistics and Matplotlib for complex charts and exported reports. Use native Qt widgets for forms, buttons, navigation, tables, and dialogs.

## 2.3 Data and content
- SQLite.
- SQLAlchemy.
- Alembic.
- Pydantic.
- JSON.
- Markdown.
- SQLite FTS5 for searchable lessons and notes.

## 2.4 AI integration

Create a provider-independent AI architecture.

Support adapters for:
- Anthropic Claude API.
- OpenAI API.
- Google Gemini API.
- Other compatible providers through adapters.

Do not bind the application to one AI provider.

AI configuration must include:
- Provider.
- Model.
- API endpoint where applicable.
- API key.
- Temperature.
- Maximum output tokens.
- Request timeout.
- Connection status.
- Model availability.

Never hardcode credentials. Store API keys securely using the operating system credential store when possible. Provide an environment-variable fallback.

## 2.5 Development and quality tools
- pytest.
- pytest-qt.
- Ruff.
- mypy.
- coverage.
- pre-commit.
- Git.

# PART 4. FILE AND RESOURCE RULES

## 4.1 Application data locations

Separate source code from user data.

Linux:
- Source: ~/PythonMastery/
- Configuration: ~/.config/python-mastery/
- Database: ~/.local/share/python-mastery/
- Cache: ~/.cache/python-mastery/
- Logs: ~/.local/state/python-mastery/logs/

Windows:
- Configuration: %APPDATA%\PythonMastery\
- Database: %LOCALAPPDATA%\PythonMastery\data\
- Cache: %LOCALAPPDATA%\PythonMastery\cache\
- Logs: %LOCALAPPDATA%\PythonMastery\logs\

Do not store important user data inside the installed application directory.

## 4.2 Content file conventions

Every course must have course.json.

Every lesson must have:
- lesson.json
- theory.md
- examples/
- exercises.json
- quiz.json
- references.json

Every project must have:
- project.json
- README.md
- requirements.md
- milestones.json
- evaluation.json

Use unique identifiers, not lesson titles, as database references.

## 4.3 Example lesson.json

{
  "id": "PY-FND-005",
  "course_id": "python_fundamentals",
  "module_id": "control_flow",
  "order": 5,
  "title": {
    "uz": "Shart operatorlari",
    "en": "Conditional Statements"
  },
  "difficulty": "beginner",
  "estimated_minutes": 45,
  "prerequisites": [
    "PY-FND-001",
    "PY-FND-002"
  ],
  "objectives": [
    "Understand conditional logic",
    "Use if statements",
    "Evaluate Boolean expressions"
  ],
  "content_file": "theory.md",
  "exercise_file": "exercises.json",
  "quiz_file": "quiz.json"
}

This is an illustrative schema. Validate all references before loading content.
